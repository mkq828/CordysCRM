# 演示账号与演示数据 — 任务清单

> 目标：给城市经理一套「企业版 + 全字段 + 多角色」的演示租户，随数据库一起发布到服务器后可直接登录给客户演示。

## 一、现状结论（已核实，2026-10-20）

| 项 | 现状 |
| --- | --- |
| 我此前截图用的账号 | `13900000001`（王伟），角色 = 销售员 + 销售经理 |
| 所在租户 | org `100001`「default」（平台内置组织，admin 超级管理员也在此） |
| 客户数 | 该租户共 **102 家**（王伟 16、admin 16、其余 5 名销售员各 14） |
| 是否企业版 | **否**。org 100001 在版本表里没有任何记录，等于「无订阅」 |

结论：现在这套「default + 销售员账号」**不能直接拿去给客户演示**——既不是企业版，数据也零散。

## 二、目标

1. 一个独立「演示租户」，绑定**企业版**（AI 月额度 1000，全功能特性集）。
2. 5 个**租户管理员**演示账号，姓名就叫「演示账号1 ~ 演示账号5」，密码统一 `123456`。
3. 数据**全字段填满**，跑通「线索 → 客户 → 商机 → 报价 → 合同 → 回款 → 发票/订单/产品/财务」完整链，并配好 AI 相关数据，能撑起每个功能演示。
4. 随数据库迁移到服务器后**立即可用**（数据就是普通租户行，`is_demo=1` 隔离，不进全局营收）。

## 三、方案决策

- **新建**独立演示租户（不复用遗留的「西安市融创文化有限公司」，它带残留测试账号）。
- 租户名用真实感示例公司名「**广州华辰科技有限公司**」，`org_type=ENTERPRISE`、`is_demo=1`。
- 演示账号全部挂 `org_admin`（租户管理员）角色，数据范围 = 全部，一个人即可演示全系统。
- 密码复用现有 bcrypt 哈希（对应明文 `123456`）。
- 种子用**幂等 SQL**（`INSERT IGNORE`），可重复执行，随库发布。
