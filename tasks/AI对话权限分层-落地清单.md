# AI 对话权限分层 — 落地清单

> 状态：方案已评审定稿，**未动代码**。
> 目标：把现有 4 个 AI 对话（军师 / 哆咪AI / 问数BI / 经营决策中枢 AI 问答坞）收敛成 **2 个入口**，拉开职责边界；老板侧升级为「AI 经营决策中枢」，从「被动查数」升级到「主动报告 + 督办闭环」。
> 关联：语义检索升级见 [[知识库语义向量检索-落地清单]]，两件事独立排期。

## 1. 现状（已核实）

| AI 对话 | featureCode | 数据范围 | 现状 |
|---|---|---|---|
| 哆咪AI（AgentChat） | `ai_chat` | 纯 LLM，不查库 | 通用闲聊对话框 |
| 军师·分析（SalesAdvisor `/analyze`） | `ai_advisor` | 不查库，分析粘贴/截图内容 | 结构化分析 + 一键转跟进 |
| 军师·查数（SalesAdvisor `/query`） | `ai_advisor` | 本人 + 下级 客户/跟进（`AdvisorDataService.getUserIdsWithSubordinates`） | 营销场景查数 |
| 问数BI（AskBi `/query`） | `ai_ask_bi` | 全 org，仅 `WHERE organization_id = ?`，无 owner 过滤 | Text-to-SQL 语义层 |
| 经营决策中枢 AI 问答坞 | — | **纯前端占位** | `BusinessChat.vue` 的 `ask()` 写死返回「AI 分析即将接入」，未接任何后端 AI 接口 |

**关键澄清**：经营决策中枢 = 两半，状态不一样：
- 可视化大屏（水母 6 维度 / 下钻 / KPI）**真查库**，后端 `BusinessScreenController` 有 3 个下钻接口（销售/区域/阶段）。
- 底部「AI 问答坞」**纯占位**，未接线（`index.vue` 只传 KPI，不监听提问事件）。

## 2. 最终分层（收敛成 2 个入口）

> 核心原则：**员工 AI = 查自己的数据 + 分析话术 + 转跟进；老板 AI = 查全公司 + 主动报告 + 下通知。**

### 2.1 员工 AI（哆咪AI）

| 项 | 值 |
|---|---|
| 谁用 | 全体员工（登录即可用） |
| 数据范围 | 本人 + 下级 客户/跟进/订单 |
| 能力1 | 查数（我的客户/跟进/订单） |
| 能力2 | 分析（截图/粘贴话术，结合查库给建议） |
| 能力3 | 一键转跟进 |
| 闲聊 | ❌ 拒绝，引导回系统业务数据 |

- 交互：**方案A**——同一个框，能力按需触发；对话顶部放快捷指令按钮（「查客户」「分析话术」「转跟进」）预填意图，兼顾显性与少切换。
- 后端 `ai_advisor` 的 featureCode、额度照旧保留，只取消前端独立入口。

### 2.2 老板 AI（经营决策中枢 AI）

| 项 | 值 |
|---|---|
| 谁用 | 租户管理员（第一版起步，权限点 `AI_BOSS:QUERY` 门控） |
| 数据范围 | 全 org 经营数据 + Text-to-SQL 明细 |
| 能力1 | 查全公司经营指标（新签/回款/漏斗） |
| 能力2 | 查明细（原问数BI 的 Text-to-SQL 语义层） |
| 能力3 | 发站内通知（AI 解析收件人+内容，**直接发送，不二次确认**） |
| 增值1 | 主动预警（环比大跌 / 大客户久未联系 / 某人多日无跟进） |
| 增值2 | 经营归因（为什么，如「转化率卡在首次跟进环节」） |
| 增值3 | 督办闭环（下达 → 跟踪是否行动 → 到期升级） |
| 增值4 | 经营晨报 / 周报（定时主动报告） |

- 边界：**只读 + 发通知**（通知是唯一写操作）。自动改业务数据（重新分配客户 / 批量发消息）先不做，等 AI 员工自动跑任务鉴权框架成熟再放。

## 3. 入口收敛清单

| 入口 | 处理 | 说明 |
|---|---|---|
| 军师 | **取消独立入口** | 分析+转跟进 能力并入哆咪AI；featureCode `ai_advisor` 与额度保留 |
| 问数BI | **取消独立入口** | Text-to-SQL 语义层原样保留，入口并入经营决策中枢 AI |
| 经营中枢 AI 问答坞 | **从占位接线** | 升级为老板 AI 助手 |

收敛后员工侧 1 个 AI 框，老板侧 1 个 AI 框。

## 4. 老板 AI 增值能力的可视化落位

> 原则：AI 结论「长在大屏上」，聊天框只是主动提问入口；AI 主动产出（预警/诊断/简报/督办）要画在大屏上。

| 能力 | 可视化呈现 | 落位（基于 `businessScreen/index.vue` 现有结构） |
|---|---|---|
| 主动预警 | 水母场景新增第 7 个「预警」节点（警示色），点开是异常卡片列表，点卡片联动下钻 | 水母场景（6 维度 → 7 维度） |
| 经营归因 | 现有 6 维度 / 下钻详情面板里，图表下方叠加「AI 诊断」区块 | 右侧 `DetailPanel` |
| 督办闭环 | 「督办看板」：下达通知 → 谁已办 / 谁逾期，进度条 + 状态色 | 独立面板（底部 AI 助手或右侧 tab） |
| 晨报 / 周报 | 首屏常驻「AI 经营简报」卡：核心指标 + 异常 + 谁欠跟进 + 建议 | 右上角 / 侧边常驻 |

- 底部 `BusinessChat.vue` 升级为「AI 经营助手」：保留问答（查全公司 + 发通知），上方挂预警/督办入口。

## 5. 权限与边界

- 老板 AI 新增权限点 **`AI_BOSS:QUERY`**，第一版只赋租户管理员（admin），后续按角色放开。
- 员工 AI（哆咪AI）登录即可用，数据范围跟随 `dataScope`（本人 + 下级）。
- 站内通知**直接发送，不二次确认**（一条通知，非改业务数据）。
- 老板 AI 写操作仅「发通知」；其余一律只读。

## 6. 优先级排期

| 版本 | 内容 |
|---|---|
| **第一版** | 查全公司 + 下通知 + 主动预警（2~3 个高价值规则）+ 督办闭环（简化版：到期提醒） |
| 第二版 | 经营归因 + 晨报/周报 |
| 后续 | 目标达成预测、客户流失预警、数字人播报（已在远期清单） |

## 7. 落地约定（避免做偏）

1. AI 结论**打字机式**流式吐字（复用现有约定），预警/诊断/简报不走一次性贴字。
2. AI 结论**可溯源**：每条预警/诊断点开能跳回对应客户/跟进数据，不让老板只看到结论看不到依据。
3. 员工 AI 用**方案A**（同框 + 快捷指令按钮），不单开军师页面。
4. 只改 `web`，不碰 `mobile`（沿用现有约定）。
5. 前端视觉对齐 printfilm 标杆（经营大屏已对齐，新增卡片/面板沿用现有 `NeuralScene`/`DetailPanel` 风格）。

## 8. 待定项

| 项 | 建议 |
|---|---|
| 预警规则首版选哪 2~3 条 | 环比大跌、大客户久未联系、某人多日无跟进 |

| 晨报/周报推送通道 | 站内信 + 经营中枢首屏卡片 |

## 9. 验收标准

- 员工只看到 1 个 AI 入口（哆咪AI），能查数、分析话术、一键转跟进，拒绝闲聊。
- 老板（admin）看到经营决策中枢 AI，能查全公司、查明细、发通知（直接发送）。
- 经营中枢水母出现第 7 个「预警」节点，点开有异常卡片，可下钻。
- 详情面板有「AI 诊断」区块，结论可溯源跳回数据。
- 督办看板能展示通知的执行进度，到期有提醒。
- 军师 / 问数BI 独立入口消失，但功能（分析转跟进 / Text-to-SQL）不丢。
- 权限点 `AI_BOSS:QUERY` 门控生效，非 admin 不可用老板 AI。
