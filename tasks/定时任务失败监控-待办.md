# 定时任务失败监控（job 吞异常）— 待办

> 状态：**暂缓，先不做**。来源：2026-10 DataEase 下线收尾时引出。

## 要解决什么
定时任务（晨报/督办/AI 员工扫描/竞品/招标/舆情等 `@QuartzScheduled` 任务）半夜跑挂时，
现在是静默失败——日志文件里只有一行 error，监控表却记「成功」，报警不响，等用户发现数据没更新才知道。

## 已做了什么（不必重做）
- `JobExecLogListener`（`cn.cordys.common.schedule`）：全局 Quartz JobListener，把每个任务的起止/耗时/成败落 `sys_job_exec_log`。
- `JobExecAlertJob`（`cn.cordys.crm.system.job`）：每天 8:30 扫当天 FAILED / RUNNING 超 30 分钟的任务，给 admin 发站内信。
- 以上来自 commit `af6e6c44f`「定时任务错峰至凌晨执行，新增执行日志监控与异常报警」。

## 卡点（为什么「别吞异常」做不了）
反编译外部依赖 `quartz-spring-boot-starter` 1.0.1 的 `ClusterQuartzJobBean.executeInternal`：
它用 `try { method.invoke() } catch (Exception e) { log.error }` 把任务方法抛的所有异常吞掉，只打日志、**不 rethrow**。

所以 job 代码就算往上抛，也会被框架这层吞掉，`JobExecLogListener.jobWasExecuted` 收到的 `jobException` 永远为 null → 永远记 SUCCESS。

=> `sys_job_exec_log` 的 **FAILED 分支对 @QuartzScheduled 任务是死的**，只有「RUNNING 超 30 分钟」这个报警还活着。

## 正确做法（真要动时二选一）
1. 改 quartz starter：让 `executeInternal` 不吞异常（rethrow）。外部 jar 改不动，要 fork 或升级依赖，影响所有任务，风险大。
2. 业务埋点：job 的 catch 里主动调 `JobExecLogService` 写 FAILED。但 job 方法拿不到当前 log id（id 存在 Quartz context 里，业务方法不接收 context），得先加 ThreadLocal 把 id 传进来。

## 结论
独立中等活，不阻塞任何功能、不影响验收。等真需要「任务半夜挂了给我报警」再按上面二选一单独设计。
