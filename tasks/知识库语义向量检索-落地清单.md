# 知识库语义向量检索 — 落地清单

> 状态：**入库 + 检索已实现**（向量列 / embedding / 融合检索），Rerank 与评测迭代待规划。
> 目标：把现在的关键词检索升级为语义向量检索，解决「同义不同词」漏召回（如「退款」vs「退费」）。

## 0. 能力范围（已收敛 · 对内检索，只做问和答）

> 本功能是对内知识检索，2026-10-15 拍板：只做「问 → 答」闭环。转人工、Rerank 精排、离线评测迭代、国能制度库特需（版本号 / 生效日期 / 大改回归）均不纳入。

**入库**：收文档 → 清洗 → 切块 → 向量化进向量库。

| 能力 | 现状 |
|---|---|
| 收文档 → 清洗 → 切块 → 向量化 | ✅ 已实现（固定分块 + 逐块 embedding 落 vector） |

**问答**：提问 → 检索 Top-K → 拼 Prompt → 生成；带引用，检索不到就不答。

| 能力 | 现状 |
|---|---|
| 检索 Top-K（向量 + 关键词融合） | ✅ 已实现 |
| 拼 Prompt → 生成 | ✅ 已实现 |
| 带引用（出处片段） | ✅ 已实现 |
| 检索不到不答（区分「库空」与「无命中」） | ✅ 已实现 |

**不纳入**：转人工、Rerank 精排、离线三率评测、Bad Case 错题本、国能版本号 / 生效日期 / 大改回归。

## 1. 现状（已核实）

- 检索链路：提问 → 中文 2-gram 切词 → `ExtAiKnowledgeChunkMapper.selectByKeywords`（SQL 关键词命中）→ 命中数排序 → top-K 给大模型。
- 表 `ai_knowledge_chunk`：`id / organization_id / doc_id / seq / content`，**无向量列**。
- 模型抽象：`LlmProvider`（`chatStream` / `generateImage`）+ `LlmProviderFactory` 按 provider 名路由，**无 embedding 能力**。
- 复用点：`retrieveContext()` 供 AI 员工复用，同样走关键词检索。

## 2. 方案（轻量，不上向量库）

- **embedding**：阿里云 DashScope `text-embedding-v3`（与千问同一 apiKey，OpenAI 兼容 `/embeddings`）。
- **存储**：`ai_knowledge_chunk` 加 `vector` 列。
- **检索**：按租户 org 加载该租户 chunk 向量 → 内存余弦相似度 → top-K。
- **兜底**：embedding 失败 / 老数据无向量时降级回原关键词检索。
- **为什么不上向量库**：CRM 单租户 chunk 量级（几百~几万），Java 内存暴力余弦毫秒级；等单租户到百万级再迁。

## 3. 迁移脚本（Flyway）

- 当前最新版本 `1.54.0_2`，下一个用 **`1.54.0_3`**。
- 文件：`backend/crm/src/main/resources/migration/1.54.0/ddl/V1.54.0_3__ai_knowledge_chunk_vector.sql`

```sql
ALTER TABLE ai_knowledge_chunk
    ADD COLUMN vector LONGTEXT NULL COMMENT '块向量(JSON数组，text-embedding-v3 默认1024维)' AFTER content;
```

> 说明：
> - 加列不阻塞，老数据 `vector` 为 NULL，由「回填 / 懒加载」补齐（见 §6）。
> - 想省空间可改 BLOB（float32 序列化，每块约 4KB；JSON 约 10KB）。当前量级 JSON 足够且便于排查。
> - 历史表是 `cordys_crm_version`，改完要重打包 app jar（老规矩）。

## 4. 接口改动清单

### 4.1 模型抽象层
- `LlmProvider` 新增 `default float[] embed(String text)`（默认抛 `UnsupportedOperationException`，同 `generateImage` 范式）。
- 千问（阿里云）provider 实现 `embed`：调 DashScope `text-embedding-v3`。
- 豆包 provider 实现 `embed`（可选）：调火山方舟 embedding。

### 4.2 数据层
- `AiKnowledgeChunk` 加字段 `private String vector;`。
- `ExtAiKnowledgeChunkMapper`：
  - 新增 `List<AiKnowledgeChunk> selectWithVectorByOrg(@Param("orgId") String orgId)`（只取 `id/content/vector`，避免大字段全量）。
  - 上传回填：新增 `updateVector(id, vector)`（或批量 update）。

### 4.3 服务层 `AiKnowledgeService`
- `upload`：分块后对每块批量 `embed` 生成向量 → 写入 `vector` 字段（含失败重试；单文档分块上限 2000 已存在，注意批量限流）。
- `retrieveChunks`：改为「向量 top-K」主路径 + 「关键词」兜底。
- `retrieveContext`：同样切向量检索。
- 新增 `embedQuery(String question)`：提问向量化。

### 4.4 模型配置（embedding 是 utility 模型，非对话模型，需独立解析）
二选一：
- 简单：`sys_parameter` 配置 `ai.kb.embedding_model`（默认 `text-embedding-v3`），复用千问 provider/apiKey。
- 规范：纳入 `AgentModelService` 模型角色体系，加 embedding 角色。
- **建议先走 sys_parameter**（改动小），后续再统一进模型配置。

### 4.5 额度计费（可选）
- embedding 按 token 计费，量小。第一版先不计费（成本可忽略），留埋点。

## 6. 老数据回填（关键遗漏点）

已上传文档的 chunk 无向量，两种补法：
- **懒加载**：检索命中某 chunk 发现 `vector=null` → 现场 embed + 落库（零停机，首查略慢）。
- **一次性回填任务**：遍历全部 chunk 批量 embed（简单可控）。
- 建议：懒加载为主，回填任务可选。

## 8. 验收标准

- 「退款」能召回「退费」同义内容（核心）。
- 上传文档后立即可语义检索。
- 老文档回填后可检索。
- 租户隔离：只检索本 org 向量，不串库。
- 出处 / 引用回填正常，模型不编造。
- embedding 失败时降级关键词检索，不报错。
