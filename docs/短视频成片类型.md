# 短视频「成片类型」方案

> 关联功能：AI 创作中心 · 短视频生成。现状代码 `frontend/packages/web/src/views/video/` + `backend/crm/.../ai/video/`。

## 背景与结论

用户反馈：短视频「知识传播还行，但宣传效果差（没画面）」。

诊断结论：**不是脚本问题，是画面策略问题。** 现网所有镜头的画面 prompt 都被锁死在「无人脸空镜 B-roll」（`IMAGE_NO_TEXT_SUFFIX` 硬编码「不要出现人物与正面人脸」），导致成片从头到尾是办公室空镜/特写/抽象画面，不承载「产品/宣传」信息。

方案：**不去 GitHub 找新 skill**（printfilm 已给完整管线），而是在短视频里新增一个租户可选的「成片类型」维度，用它切换背后的脚本结构与画面 prompt 策略。模型不变（仍 Seedream 出图 + Seedance 图生视频）。

## 成片类型（4 种）

| 类型 | 枚举值 | 脚本结构 | 画面策略 | 状态 |
|---|---|---|---|---|
| 口播科普 | `talk` | 一段式口播，钩子+讲利益 | 空镜/场景氛围/产品特写 B-roll（现状） | 默认，已支持 |
| 产品讲解 | `product` | 按「卖点」逐条切镜 | **画面必须出现产品主体**（特写/使用场景/细节） | 本期落地 |
| 情景剧 | `scenario` | 短剧式：钩子→冲突/痛点→解决→行动 | **有人物（1~2 固定角色）+ 场景 + 动作** | 本期落地 |
| 漫剧 | `comic` | 多人物、对白、故事传播 | 角色一致性要求最高 | 占位「即将上线」，延后 |

## 我的决定（含理由）

1. **本期只落地 `talk` / `product` / `scenario` 三种**，`comic` 下拉占位禁用。
   - 理由：产品讲解/情景剧能立刻解决「宣传效果差」痛点，改动小（切换 prompt 策略 + 脚本模板）；漫剧卡在「多人物跨镜头脸不能变」，需先做人物一致性（参考图锁定 + Seedance subject reference），单独里程碑。
2. **「成片类型」做成选题页一个下拉**，与「模板」「成片方式」平级，选完传后端 `videoType`，不改模型选择逻辑。
   - 理由：类型决定「怎么写脚本、怎么出画面」，与「用哪个模型」正交。
3. **产品讲解默认强制画面带产品主体、情景剧默认强制有人物**，写成 prompt 硬约束，不让 AI 自由掉回空镜。
   - 理由：本次「没画面」正是 AI 默认选最安全的空镜，必须用硬约束压住。

## 落地改动清单

### 后端

- 新迁移 `V1.43.0_6__ai_video_task_video_type.sql`：`ai_video_task` 加 `video_type VARCHAR(20) NOT NULL DEFAULT 'talk'`。
- `VideoGenerateRequest` / `AiVideoTask` / `VideoTaskResponse` 增 `videoType` 字段。
- `VideoGenerateService`：
  - 新增 `VIDEO_TYPE_*` 常量 + `normalizeVideoType`。
  - `buildScriptMessages` / `buildImageDescMessages` 按类型选 system prompt。
  - `generateOneImage` / `effectiveVideoPrompt` 按类型选画面约束后缀（替换硬编码 `IMAGE_NO_TEXT_SUFFIX`）。
  - 新增三段 system prompt：`SCRIPT_SYSTEM_PROMPT_PRODUCT`、`SCRIPT_SYSTEM_PROMPT_SCENARIO`、`IMAGE_DESC_SYSTEM_PROMPT_PRODUCT/SCENARIO`（或一个分支方法）。

### 前端

- `lib-shared/models/ai.ts`：`AiVideoGenerateParams` / `AiVideoTask` 增 `videoType`。
- `web/src/views/video/index.vue`：选题页加「成片类型」下拉（4 项，`comic` 禁用「即将上线」）；`form.videoType` + 提交参数。
- `locale/zh-CN.ts` / `en-US.ts`：补类型名与说明。

### 顺带：生成改为顺序队列

- 出图（原 4 并发）与逐镜视频（原 3 并发）统一改回**按分镜顺序逐个生成**，避免对外部模型服务并发触发限流/失败，进度按镜号确定性推进。
