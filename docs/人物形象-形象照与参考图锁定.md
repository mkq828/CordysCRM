# 人物形象地基：形象照上传 + 参考图锁定

> 关联功能：AI 创作中心 · 短视频生成（功能 7）。本文是「人物形象」这条公共地基的 PRD，同时服务 **数字人**（老板本人出镜）与 **漫剧/情景剧**（角色一致性）。

## 背景与目标

短视频成片类型里，`情景剧`/`漫剧` 需要「人物在场景里做动作、跨镜头脸不变」，数字人需要「老板本人形象出镜」。两者共用一个底层能力：

**租户上传自己的形象照 → 生成时把形象照作为「参考图」注入出图/出视频 → 让生成的人物长得像本人。**

核心收益：

1. **零侵权**：用租户本人的形象，规避明星/素人肖像权。
2. **人物一致性**：跨镜头「脸不变」，这是漫剧/情景剧的命门。
3. **为数字人铺路**：形象照是数字人（真人录制 + 口型驱动）的轻量前置，两者复用同一份形象资产。

## 技术路径（两层）

| 层 | 能力 | 现状 |
|---|---|---|
| 参考图驱动文生图 | 形象照作为 Seedream 图生图/参考图输入，让场景人物长得像本人 | 需实测参数/接口 |
| 参考图驱动图生视频 | 形象照作为 Seedance subject reference，视频里人物保持一致 | 需实测参数/接口 |
| 换脸（后处理） | FaceFusion / InsightFace inswapper 对成片后处理换脸 | 备选，参考图路线不够再上 |

## 关键决策（含理由）

1. **先做「参考图锁定」，换脸作为后处理备选**，不优先。
   - 理由：参考图路线更干净（生成时直接带形象），换脸是后处理，多一道工序且易糊脸。
2. **形象照做成租户级资源，上传管理 + 任务可选引用**，默认不强制（口播科普可不出人物）。
   - 理由：不是所有成片都要人物，做成可选项不破坏现有流程。
3. **上传时必须勾选「本人或已获授权」**（合规提示）。
   - 理由：防止拿别人照片换脸，把授权责任落到上传者。
4. **里程碑 M1→M2→M3 依次验证再扩**，不一次铺开。
   - 理由：Seedream 参考图 / Seedance subject reference 的具体参数受模型版本限制，先跑通最小闭环，避免盲写一大片。

## 数据模型

- 新表 `ai_character`（人物形象资产，按 org 隔离）：`id / organization_id / name / attachment_id(形象照) / is_default / create_user / create_time / update_time`。
- 任务关联：`ai_video_task` 加 `character_id`（可空，选了就用该形象照当参考图）。

## 里程碑

- **M1 · 形象照上传 + 出图参考图**：形象照上传落库 → 短视频出图时按 `character_id` 取参考图 → Seedream 参考图模式生成带本人形象的画面。验证「出图长得像本人」。
- **M2 · 出视频 subject reference**：Seedance 传 subject reference，验证「视频跨镜头人物一致」。
- **M3 · 升级数字人**：同一形象照 + 声音克隆（功能 11）→ 2D 真人感数字人（真人录制 + AI 口型驱动），做「老板本人出镜口播」。

## 验收口径

- M1：上传本人正脸照 → 选「产品讲解/情景剧」+ 勾选该形象 → 出图画面人物与本人相似、跨镜一致。
- M2：同一形象照 → 逐镜 Seedance 出视频 → 视频里人物脸不漂移。
- M3：数字人用本人形象 + 克隆声音，口型与语音对齐。

## 边界与后续

- Seedream 参考图 / Seedance subject reference 的接口能力需实测，若受限则退到 M1 用「文生图 + 提示词强化」过渡，M2 换脸后处理兜底。
- 多人剧情（漫剧多角色）需要多张参考图 + 角色绑定，属 M2 之后的能力扩展。
