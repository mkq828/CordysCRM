# 企业版商业化与 AI 额度 PRD

> 版本：v0.2（讨论稿，待评审）
> 状态：设计已敲定，字段/规则待细化落地
> 相关模块：平台运营端（收费/合同/到期/城市经理业绩）、AI 营销模块、短视频获客、AI 额度计量、通知体系

---

## 1. 背景与目标

CordysCRM 作为多租户 SaaS，需要一套「平台收租户的钱」的商业化闭环，让租户付费开通企业版，并形成 签约 → 收费 → 开通 → 续费 的可持续营收。

**核心区分（两层账，勿混）**：

| 层 | 含义 | 现状 |
|---|---|---|
| 租户账 | 租户收自己客户的钱 | 已有财务应收模块 + 回款核销 |
| **平台账（本 PRD）** | 平台收租户的钱 | 待建，复用回款核销逻辑 |

**目标**：
1. 企业版订阅收费、签合同、回款、开票、到期续费全流程线上化。
2. 城市经理推广 + 业绩统计，离职可交接、业绩可对账。
3. 用「增值业务」让客户觉得价有所值：获客 + 签单 + 传播 + 降本四条主线。
4. AI 的 token 成本由平台打包进订阅价，用额度体系控制成本、防刷、可核算。

---

## 2. 角色与权限

三层角色体系（叠加在现有 admin / org_admin 之上）：

| 角色 | 层级 | 说明 |
|---|---|---|
| `admin` | 平台超管 | 硬编码超管，凌驾所有角色；可配全局参数、看全部营收/成本、二次分配客户 |
| `city_manager`（城市经理） | 平台员工 | 新增。负责推广、签合同、跟进租户；看自己名下租户业绩 |
| `org_admin` / 租户子账号 | 租户侧 | 已有。付费租户，登录使用 CRM 与 AI 模块 |

**权限红线**：
- 营收/成本看板、模型单价表：**仅 admin 可见**。
- 租户端 AI 只看到「次数」，看不到金额。
- 城市经理只能看自己归属的租户，不能跨看。

## 3. 套餐与版本

**定价模式：按功能版本，坐席不限数量**（目标客户为中小公司，大公司自研系统）。

| 版本 | 定位 | 软上限 | 建议年价 |
|---|---|---|---|
| 基础版 | 引流 | 5 人 | 免费（含 20 次 AI 试用） |
| 专业版 | 渗透主力 | 10 人 | 3980/年（大环境差可首年 2980 促销） |
| 企业版 | 利润主力 | 30 人（超出单独商务谈） | 9800/年 |

**三版功能划分**：

| 能力 | 基础版 | 专业版 | 企业版 |
|---|---|---|---|
| 基础 CRM | ✅ | ✅ | ✅ |
| 高级财务/回款核销 | ❌ | ✅ | ✅ |
| 销售 SOP + 跟进提醒 | ❌ | ✅ | ✅ |
| 自定义字段 + 报表导出 | ❌ | ✅ | ✅ |
| 短信/企微通知 | ❌ | ✅ | ✅ |
| AI 客户军师 + 候选话术（手动上传聊天） | ❌ | ✅ | ✅ |
| AI 获客内容生成（选题/文案/图文） | ❌ | ✅ | ✅ |
| 销售话术库（RAG） | ❌ | ✅ | ✅ |
| 短视频生成（基础额度，手动发布） | ❌ | ✅ | ✅ |
| AI 月额度 | 试用 20 次 | 约 300 次 | 约 1000 次 |
| 企微会话自动分析（全自动） | ❌ | ❌ | ✅ |
| AI 方案/PPT 演示生成 | ❌ | ❌ | ✅ |
| 线索爬取 + 竞品/行业洞察 | ❌ | ❌ | ✅ |
| 私信获客画像（抖音/快手/小红书，Beta 尝鲜） | ❌ | ✅ | ✅ |
| AI 员工 + 语音外呼 | ❌ | ❌ | ✅ |
| 企业知识库（RAG + 文档解析） | ❌ | ❌ | ✅ |
| 数字人/剪辑/爆款复刻（基础额度，超量加购） | ❌ | ❌ | ✅ |
| 专属支持 | ❌ | ❌ | ✅ |

- 软上限为「商务兜底」，非硬限制；超限客户单独谈。
- 版本升级：**按剩余时长比例补差价**（替代坐席增购，因坐席不限）：
  `补差 = (目标版年价 - 当前版年价) × (剩余天数 / 365)`

### 3.1 版本与功能的可配置管理

价格、软上限、功能归属均由 **admin 后台可维护**，不写死在代码里。配 4 个关键设计：

1. **功能标识结构化**：每个功能一个唯一 `feature_code`；「版本」是一组 feature_code 的预设模板，admin 只能勾选「哪个功能属于哪个版本」。
2. **版本快照**：租户开通时快照「当时的版本名 + 价格 + 功能集合」写入租户记录；admin 改价格/功能**只影响新开通和后续续费**，已开通租户按快照走；续费时按当时的版本新价格 + 新功能集合重新快照。
3. **全局开关 vs 版本归属**（两个维度）：版本归属 = 某功能在哪些版本可用；全局开关 = 某功能整体下线（如私信获客平台侧故障），admin 一键全局禁用，不受版本影响。
4. **审计日志**：价格/功能归属的每次修改落 `sys_operation_log`（复用 traceId 机制），记录操作人/时间/变更内容。

**数据模型（4 张表）**：
```
sys_edition          版本表（code / 名称 / 年价 / 首年促销价 / 软上限）
sys_feature          功能表（feature_code / 名称 / 分类 / 全局开关）
sys_edition_feature  版本-功能关联表（多对多）
tenant_edition       租户版本快照（版本名 / 价格 / 功能集合JSON / 起止时间 / 状态）
```

## 4. 增值业务地图（四条主线）

按「token 成本」分两类，决定「打包进订阅」还是「按量加购」：

| 类型 | token 成本 | 商业处理 |
|---|---|---|
| 文本类（几分钱/次） | 极低 | **打包进订阅价**（含月额度） |
| 生成类（几元/次） | 高 | **按量加购增值包** |

| 主线 | 增值业务 | 来源项目 | 成本 |
|---|---|---|---|
| **获客**（找客户） | AI 获客内容生成（选题/文案/图文） | marketingskills、自媒体 5 skill、AiToEarn | 低 |
| | 线索爬取 + 竞品/行业洞察 | scrapling、browser-use、MiroFish、WeMM | 中 |
| **签单**（成交） | AI 客户军师 + 候选话术 | 狗头军师、jev-chat-jarvis | 低 |
| | 企微会话自动分析 | 存档 API + 上述两个 | 低 |
| | 销售话术库（RAG） | WeKnora | 低 |
| | AI 方案/PPT 演示生成 | dashi-ppt、anydoc | 低 |
| **传播**（品牌） | 数字人口播视频 | LongCat、avatar-forge | **高** |
| | 实时交互数字人 | OpenTalking、LiveTalking | **高** |
| | 短视频自动剪辑 / 爆款复刻 | FFmpeg、OpenMontage、hypit | **高** |
| | 声音克隆 | VoxCPM | 高 |
| **降本**（内部效率） | AI 员工（144 员工） | agency Agents、metagpt | 中 |
| | AI 语音外呼 / 客服 | SpeechToSpeech | 中 |
| | 企业知识库 + 文档解析 | 腾讯 WeKnora、anydoc | 低 |
| | AI 分身 / 语气克隆 | WeClone、parents-skills | 中 |

> 其余（code-review、spec-kit、superpowers、skill-up 等）是平台内部开发提效工具，不进租户功能。

## 5. 合同与签约

**双模式并存**：

| 模式 | 流程 | 费用 | 优先级 |
|---|---|---|---|
| 纸质合同 | 平台生成 PDF → 快递 → 客户盖章回寄 → 上传扫描件归档 | 快递费 | **第一版主推** |
| 电子合同 | 对接签约宝 / e签宝 / 法大大 / 上上签：实名 → 发起签署 → 双方签署 → 回调归档 | 约 5–15 元/份 | 可选（二期） |

**合同状态机**：
```
草稿 → 待签署 → 部分签署 → 已完成 → 已归档
                              └→ 已作废
```

**字段（合同主表）**：合同编号、租户主体信息（企业全称/统一社会信用代码/法人/地址）、套餐版本、订阅时长、金额、签约城市经理、签署方式、状态、附件（PDF/扫描件）。

**备注**：合同/发票依赖「租户主体信息」采集校验；平台收款主体（公司全称 + 对公账户 + 开票抬头）上线前填入。

## 6. 回款与发票

**回款**：复用现有 `contract_payment_record` 回款核销逻辑（收款账户 + 付款凭证 + 核销/撤回），但作为「平台收款」独立一层账。

- 收款方式：对公转账 / 支付宝 / 微信（线上含约 0.6% 手续费与结算周期）/ 线下。
- 支持**分期付款**（首付 + 尾款 / 多期计划）。
- 回款确认后**自动开通企业版 + 写生效/到期时间**。

**发票**：普票/专票、开票金额、税点（6% 增值税）、开票状态（未开/已开/作废）。

**三个金额口径须分开记录**：合同金额（应收）、实收金额（现金流）、开票金额（发票），三者可能不一致。

## 7. 开通 / 试用 / 到期

**可配置项（admin 后台配置）**：

| 配置项 | 默认 | 作用域 |
|---|---|---|
| 试用期天数 | 30 天 | 全局默认 + 套餐覆盖（套餐优先） |
| 续费提醒提前天数 | 7 天 | 全局 |
| 宽限期 | 3 天 | 全局 |
| AI 试用次数 / 每日上限 | 20 次 / 5 次 | 全局，可调 |

- 开通时把「当前配置」**快照写入租户的 `expire_time`**，改配置只影响新开通租户，不影响历史（避免到期时间漂移）。

**到期禁用**：
- 到期后租户账号 + 子账号无法登录（或见「已到期，请续费」页），**API/接口一并停**。
- 到期页展示「开通请联系：{归属城市经理姓名 + 电话}」，动态渲染。

**数据保留**（口径统一）：
- 对外话术：到期后数据保留 90 天，90 天内续费完整保留。
- 对内策略：**不物理删除，仅逻辑隔离 + 停访问**，数据作为系统积累。

**续费**：从原到期日顺延（非续费当天重算）；续费后自动解禁。

## 8. 城市经理体系

**归属字段（租户表）**：

| 字段 | 含义 | 是否随二次分配转移 |
|---|---|---|
| `sign_manager_id` 签约城市经理 | 谁签的单 | ❌ 永久不变 |
| `follow_manager_id` 当前跟进城市经理 | 日常维护 | ✅ 二次分配时改 |

**业绩口径（定死，避免对账混乱）**：
- **签约业绩**（签约客户数、签约金额）：永久归**签约**城市经理，离职仍可查。
- **续费/回款业绩**：归**当前跟进**城市经理。
- 二次分配只改 `follow_manager_id`，不改 `sign_manager_id`。

**离职处理**：
- 账号 `disable`（禁止登录），历史签约归属保留。
- 名下租户由 admin **二次分配**给在职城市经理，操作留痕（traceId + 审计日志）。

**业绩看板（平台端，admin 可见）**：按城市经理聚合三个维度——签约客户数、合同金额、回款金额；支持按周/月/年。

## 9. AI 额度体系

### 9.1 模型接入
- 模型做成**可配置适配层**，支持千问 / DeepSeek / 豆包（火山引擎）等，换模型改配置不改业务代码。
- **单价表可配置**（手动改，不做实时自动同步；厂商调价后 admin 手动更新 + **每月对一次实际账单校准**）。

### 9.2 计量口径
- **对内**：按模型返回的 `usage` 字段，`input token` 与 `output token` **分开记账**（输出更贵）。
- **对外（租户可见）**：按「次数」展示，不暴露 token 数。
  - `1 次标准 AI 调用 ≈ 折合 X 万标准 token`（X 可配）；重任务（长文本、批量、生成类）按实际 token 倍数扣次数。

### 9.3 额度模型（月配额 + 加购包）
- 各版本**每月含固定 AI 额度，次月 1 日重置**。
- 示例量级：企业版月配额 1000 次、1 次 ≈ 1 万 token，月成本约千万级 token ≈ 国产模型几十元，订阅价覆盖绰绰有余（示例值，待定）。

### 9.4 超量策略（分级，不一刀切）
| 阶段 | 处理 |
|---|---|
| 正常（≤100%） | 正常使用 |
| 软超（100%–110%） | 仍可用，限速 + 横幅提示「额度将尽」 |
| 硬超（>110%） | 停 AI 高级功能，弹「额度已用完，加购或升级」 |

### 9.5 加购 / 充值
1. **加购额度包**（如 +100 次 / 99 元），走回款闭环。
2. **升级版本**（额度更高）。
3. **等次月重置**自然恢复。

### 9.6 防刷 + 熔断（成本安全网）
- 单租户**每分钟 / 每日限流**。
- **单日成本熔断**：某租户单日 token 成本超阈值 → 自动暂停该租户 AI + 平台告警。

### 9.7 用量与成本看板
- **租户端**：本月已用 / 剩余 / 每日趋势 / 分模块用量；进度条 80% 预警。**只看到次数，看不到钱**。
- **平台端（仅 admin）**：每个租户真实 token × 模型单价 → 折算实际费用，按租户/天/汇总；标注「估算」；识别「用量接近甚至超过订阅价」的亏损租户。

## 10. 短视频获客闭环（新增）

**完整闭环**：
```
生成短视频（素材+要求→AI出视频+各平台文案）
   → 租户手动发布（不自动发布，自动发布会封号）
   → 私信来咨询 → 自动读私信 → AI 画像
   → 进 CRM 客户池 → AI 客户军师跟进 → 签单
```

### 10.1 短视频生成
- 租户上传素材（图片/文案/音频）+ 要求 → 生成短视频 + 抖音/快手/小红书/朋友圈配套文案。
- 生成后**用户自己下载、手动发布**（明确不做全自动发布，防封号）。
- 来源项目：LongCat-Video-Avatar、avatar-forge、hypit、OpenMontage、FFmpeg（优先评估 LongCat / avatar-forge）。

### 10.2 私信获客画像（集成 16.test）
- 参考项目 `16.test`（抖音私信获客画像系统，Phase 1 抖音、Phase 2 快手/小红书）。
- 能力：Playwright 扫码登录 → 读租户**自己账号**的私信 → DeepSeek 画像（性别/年龄/品类/话术）→ 导出/进 CRM 客户池。

**三个硬约束（务必认清）**：
1. **只能拿租户自己账号的私信**，不是全网爬别人数据。
2. **封号风险实打实**（浏览器自动化），必须「租户自担风险 + 小号先试 + 控制频率 + 平台免责」。
3. **DOM 改版 = 持续维护成本**（抖音前端频繁迭代）。

### 10.3 提取层升级（集成 scrapling）
- 用 `#20 scrapling`（自适应爬取框架）替换 16.test 的硬编码 `SELECTORS`：
  - `scrapling Fetcher(playwright_page=已登录页面)` 复用登录态，`Adaptor` 自适应提取。
  - 改版时维护成本从「改代码」降为「偶尔重标定特征」。
- **务实边界**：scrapling 降低「选择器失效」维护，**不解决**反自动化风控、登录态过期、SPA 渲染、媒体解密；抖音大改版仍需重新适配。

### 10.4 集成架构（Python 微服务）
```
[租户A抖音profile] ┐
[租户B抖音profile] ├─→ Python 获客微服务（独立进程）──HTTP──→ Java CRM
[租户C小红书...]   ┘        │ Playwright 按租户隔离登录态
                           └→ 私信落库 → DeepSeek画像 → 推给 CRM 客户池
```
- 多租户登录态隔离（每个租户一个 profile，登录态会过期需定期重新扫码）。
- 资源消耗：每租户一个 Chromium 实例（几百 MB 内存），30 租户需 8–16GB 内存起步。

### 10.5 商业化定位
- **短视频生成**：专业版含基础额度、企业版更多，高成本（数字人/剪辑）走增值包加购。
- **私信获客画像**：**专业版起含（Beta 尝鲜定位），企业版也含**。因不稳定，不当作任一版本的核心付费卖点；封号风险靠平台侧「免责声明 + 小号建议 + 采集频率上限 + 单租户限流」控制，不靠版本限制。

## 11. 企微会话分析

**双方案并存，租户自选**：

| 方案 | 数据源 | 适用 |
|---|---|---|
| 手动上传 | 粘贴聊天文本 / 截图 OCR | 未开通企微存档的租户 |
| 企微 API 自动获取 | 会话内容存档 API（租户自付存档费） | 已开通企微存档的租户 |

- 未开通企微时，手动上传页顶部展示引导卡：**「开通后分钟级自动获取对话记录、实时分析，无需手动上传」** + 对比表 + 开通按钮。
- 开通按钮进入企微绑定流程（填 corpId/secret/存档密钥 → 校验 → 开通）。
- 分析维度（v1 优先前 6 项）：意向度评分、成交信号、异议点、情绪/满意度、竞品提及、沉默/流失风险；后续补 需求关键词、采购流程、员工跟进质检、客诉预警。

> 存档费由租户自行承担（服务版约 900 元/人/年，可只给对接客户的 1–2 名销售开通），平台只提供「存档 SDK 集成 + AI 分析」能力。企微是官方合规 API，与短视频私信获客的「浏览器自动化」性质不同。

## 12. 通知体系

**三通道**：站内信 / 短信（阿里云）/ 企业微信。

- **模板可配置**：模板 code + 内容 + 变量占位，三通道各一套。
  - 短信受阿里云**模板审核**限制 → 固定模板 + 变量，半固化。
  - 企微 / 站内信可全量自由配置。
- **通道可开关**：本地开发企微关（受「企业可信 IP」限制 errcode 60020）、短信开（阿里云不受 IP 限制）；上线后开企微。
- 典型通知：企业注册审核通过、到期提醒、续费提醒、AI 额度告警。
- 短信成本：约 0.04 元/条，按条计费；需企业签名 + 模板审核。

## 13. 账号安全（防一个账号全公司共用）

**单点登录：会话令牌唯一化，不用 IP 做主判据**（IP 会因 4G/WiFi 切换、公司 NAT 误判）。

- 登录时后端签发唯一 `sessionId`，记为该账号「当前有效会话」。
- 同账号二次登录 → 旧 `sessionId` 置失效。
- 旧端请求携带失效 sessionId → 返回特定错误码 → 前端弹「该账号已在其他设备登录，请联系管理员」。
- IP 仅作**辅助风控记录**（异常频繁切换告警），不参与踢人。

**边界**：单点登录防「同时共用」；「轮流共用」需设备指纹 + 切换频次告警，投入产出比低，先不做，软上限 30 人兜底。
