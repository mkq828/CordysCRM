## 一、密钥加密方案（代码已落地，部署时激活）

### 1. 已实现

- 新增通用加密工具 `SecretCipher`（`cn.cordys.common.util.SecretCipher`）：
  - **AES-256-GCM 认证加密 + 每次随机 12 字节 IV**（杜绝旧 `CodingUtils` 固定 IV 复用风险）。
  - 密文带 `enc:v1:` 版本前缀，便于后续密钥轮换与向后兼容。
  - 主密钥从环境变量 `CORDYS_CRYPTO_MASTER_KEY`（或系统属性 `cordys.crypto.master-key`）读取。
  - **未配置主密钥时加密降级为原样明文存储**，只打印一条 WARN——保证本地开发无感、且避免「拿公开默认密钥假加密」的隐患。
- 已接入三处敏感字段（写时加密、读时解密）：
  - `agent_model.api_key`（AI 模型第三方 API Key，所有 LLM/ASR 调用来源）
  - `ai_call_review_config.secret_key`（通话复盘回调 HMAC 密钥）
  - `user_key.secret_key`（个人中心 API Key 的 secret）

### 2. 部署时必做

- [ ] 生产环境注入强随机主密钥（≥32 位随机串，越随机越好）：
  ```bash
  export CORDYS_CRYPTO_MASTER_KEY="<生成一个强随机串，例如 openssl rand -base64 48>"
  ```
- [ ] 主密钥写入密钥管理/部署配置（K8s Secret、环境变量注入、CI 变量等），**不要**提交进仓库、不要写进镜像。
- [ ] 主密钥一旦设定**不可再更改**（改了会导致已加密的密钥无法解密）。确需轮换需配套数据迁移脚本。
- [ ] 验证：启动日志**没有**出现「未配置加密主密钥…降级为明文存储」这条 WARN。

### 3. 存量明文密钥一次性迁移

`SecretCipher.decrypt` 对无 `enc:v1:` 前缀的明文**原样返回**，所以老数据不迁移也能继续用（惰性兼容）。要一次性把存量明文刷成密文：

- [ ] 上线前在**配置好主密钥后**，触发一次批量迁移（遍历 `agent_model` / `ai_call_review_config` / `user_key` 三张表，对非 `enc:v1:` 开头的值调用 `SecretCipher.encrypt` 写回）。
- [ ] 迁移前先全量备份库；迁移后抽查各 AI 功能（会话军师、通话复盘、模型设置）能正常取到密钥。

### 4. 遗留项（完整审计再处理）

- [ ] `EncryptUtils` / `CodingUtils` 仍用**硬编码密钥 `www.fit2cloud.cn` + 固定 IV `1Av7hf9PgHusUHRm`**（GCM 固定 IV 复用属高危）。本次不动它，是因为改密钥会破坏存量已加密数据，需要与数据迁移一并设计。已登记到完整审计。

- [ ] 建立「高危漏洞 → 升级依赖 → 重新扫描」的响应约定（发现 high/critical 在发版前处理）。

## 三、运维侧备份清单

### 1. 必备份数据（按重要性排序）

- [ ] **MySQL 数据库**（`cordys-crm` 库，客户/订单/合同等核心业务数据）
  - 每日全量 `mysqldump --single-transaction --master-data=2`；
  - 开启 binlog，按小时增量备份 + 保留 binlog；
  - 保留策略建议：日备份保留 30 天，周备份保留 12 周。
- [ ] **附件 / 文件目录**（`-Dcordys.file.dir` 指向的目录，上传的录音、凭证、附件等）
  - 与数据库**同步备份**，二者缺一不可（库里存的是附件引用）。
- [ ] **Redis**：会话、验证码、限流计数等，可重建；如保存了业务态则纳入备份。
- [ ] **配置与环境变量**（含 `CORDYS_CRYPTO_MASTER_KEY`、数据源、Redis 密码）——单独加密备份，丢失则无法解密密钥。

### 2. 备份策略

- [ ] 备份文件异地/异机存放（本机备份 ≠ 备份）。
- [ ] 备份文件加密（防备份泄露二次泄密）。
- [ ] **定期做恢复演练**（恢复出的库能启动、能登录、附件能打开才算数）。
- [ ] 备份脚本里不得明文写数据库/Redis 密码，走环境变量或密钥管理。

## 四、服务端口限制清单

> 原则：对外只暴露最少端口，其余只监听内网/本机。

- [ ] **对外（公网）仅开放**：80/443（Nginx / 网关，全站强制 HTTPS + HSTS）。
- [ ] 后端应用端口（如 8081）**不对公网开放**，仅内网/回环，由 Nginx 反代。
- [ ] **MySQL（3306）**：`bind-address=127.0.0.1`，只监听本机；生产账号最小权限、禁止远程。
- [ ] **Redis（6379）**：设强密码、`protected-mode yes`、`bind 127.0.0.1`，不暴露公网。
- [ ] **SSH（22）**：改默认端口或仅允许运维来源 IP（安全组/防火墙白名单），禁止密码登录改密钥登录。
- [ ] 云安全组 / 防火墙出方向默认拒绝，按需放行。
- [ ] 管理类端口（注册中心、监控、面板）一律内网访问或加 IP 白名单 + 鉴权。

## 五、弱密码与账号清单

- [ ] **数据库**：生产 root/业务账号用强密码，删除或禁用测试账号与默认账号。
- [ ] **Redis**：`requirepass` 设强密码（当前示例密码为开发用，生产必须更换）。
- [ ] **服务器**：SSH 改密钥登录、禁用 root 直接登录（用普通用户 + sudo）。
- [ ] **应用管理员**：后台管理员账号改强密码、开启登录失败锁定、定期轮换；首次部署强制改密。
- [ ] 第三方平台（对象存储、短信、AI 厂商）的 AK/SK 均用**子账号 + 最小权限 + 定期轮换**。
